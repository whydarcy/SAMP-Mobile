# Полный веб-кэш Sile в GTA 2.10

По запросу пользователя в клиент подключён полный статический каталог `Assets/webview` установленного Sile Online 1.8.5: все JavaScript-модули, CSS, шрифты, изображения, звуки и видео. Это ресурсы интерфейса. В исследованном кэше нет отдельного движка CEF; Android-рендерер нашей сборки — WebView, игровой движок — GTA 2.10.

Исходная копия находится в `E:\samp-mobile\port\ui-sources\sile-online`. Оригинальный кэш приложения Sile не изменён. Архивы `webview-cache.tar` и `webview-media.tar` — снимки только статических UI-файлов, без данных аккаунта.

`port/tools/import-sile-ui.py` помещает весь набор в `app/src/main/assets/sile-cache`. `manifest.json` и `port/reports/sile-cache-import.json` содержат полный перечень файлов, размеры, SHA-256 оригиналов и упакованных версий. Импорт автоматически запускается при `Build-Apk.ps1`; APK содержит ресурсы и не требует установки Sile на телефоне.

## Адаптация

- Точка входа GTA: `app/src/main/assets/webui/sile/index.html`, исходник — `webui/sile/index.html`.
- `webui/src/sile.js` подключает собственный Vue-runtime и engine event bus из кэша Sile к нашему протоколу Java/JNI/C++.
- В Sile bootstrap запускаются HUD, уведомления и чат. Сторонний загрузчик игры, авторизация Sile, удалённая настройка CDN и отладочная консоль при старте не запускаются.
- Для динамических изображений, плиток карты, звуков и видео используется базовый путь `/assets/sile-cache/`. Собранные GTA-скрипты имеют абсолютный путь `/assets/webui/`, чтобы базовый путь кэша не менял их загрузку.
- По умолчанию используется мобильный вариант HUD Sile, не legacy-тема. Нативный блок PlayerInfo GTA и прежний чат скрываются после готовности Sile. Радар, органы управления, textdraw и надписи игроков остаются нативными. Панель `>>`, список игроков и серверные диалоги перенесены в веб-интерфейс.
- Передаются реальные здоровье, броня, деньги, оружие, боезапас, имя/ID, онлайн и скорость. На карту MainMenu передаются координаты игрока. Угол и интерьер пока не подключены к этому событию.
- Игровая клавиатура взята из кэша Sile. Android IME работает через обычное DOM-поле WebView, без Unity. Скрытие IME синхронизируется с состоянием Sile.
- Входящие сообщения SA:MP показываются в чате Sile; отправка текста/команд использует наш CNetGame. При старте воспроизводится ограниченная история сообщений подключения. Во время проверки обычные сообщения в чат не отправлялись.
- Кнопка «Меню» открывает настоящий `MainMenu`; «Команды» — штатный диалог Sile с `/spawn`, `/respawn`, `/tp`, `/veh` и выбором клавиатуры.
- Локальные UI-звуки `Sound_Create2D` воспроизводятся из включённых звуковых файлов. Внешние URL не используются; пространственные игровые звуки Unity не переносились.

## Границы готовности

Полный набор фронтенда включён в сборку. Серверные функции Sile — инвентарь, магазин, имущество, банковские операции, задания и другие сервисы — не реализованы нашим тестовым Pawn-сервером. Их неизвестные RPC не транслируются в SA:MP. Наличие окна в APK не означает готовность соответствующей серверной функции. Расположение и маркеры самой карты Sile ещё требуют согласования с импортированной картой GTA.

Клавиши и касания блокируются только на время открытого окна. После закрытия управление возвращается. При остановке игрового цикла интерфейс скрывается; кнопка «Возобновить» GTA остаётся доступна. При ошибке загрузки Sile контроллер восстанавливает нативный HUD и открывает предыдущий интерфейс Vue как резервный.

Сетевая загрузка страниц и ресурсов WebView заблокирована. Все статические ресурсы читаются из APK. Изменения исходного кэша ограничены адаптацией стартовой страницы и путей медиа; SHA-256 каждого изменённого файла отражён в манифесте.

Сборка проверяется в BlueStacks Android 11 / ARM64. Работа на физических устройствах и адаптация Android IME до Android 11 отдельно не проверялись.

Пути файлов проверяются по оригинальным TAR-архивам. Индекс `paths.json` разрешает пути без учёта регистра внутри каталога Sile; это сохраняет совместимость с его запросами и именами файлов на Windows. Имена с кириллицей восстанавливаются в UTF-8. Итоговый отчёт: `port/reports/sile-full-runtime.json`; проверка состава APK: `port/reports/sile-full-package-check.json`.

## Панель управления и SA:MP-диалоги

Кнопка `»` раскрывает панель в тёмном стиле Sile с золотыми акцентами. TAB запрашивает настоящий список игроков; ALT/H/Y/N/F/G/2 повторяют действия прежних нативных кнопок, ESC отменяет выбор textdraw. Кнопка «Пример диалога» открывает локальное демонстрационное окно без отправки RPC. Нативная синяя панель отключается только после готовности Sile и возвращается при резервном интерфейсе.

Входящий RPC DialogBox отображается компонентом Window для всех шести стилей SA:MP. Стиль TABLIST без заголовка сопоставлен с `list_normal`, поскольку штатные типы 4 и 5 кэша Sile оба подразумевают заголовок. Ответ сохраняет исходный ID сервера и проверяется по токену актуального окна. Текст выбранной строки берётся из исходного сообщения на игровом потоке, а не из HTML Sile. Ввод кодируется Windows-1251, ограничен 255 байтами; пароль передаётся только при явном нажатии пользователем и не пишется в журнал ответов. При перезапуске WebView актуальный диалог воспроизводится, при сбое возвращается нативное окно.

Сервер по умолчанию: `s1.sile.games:7777`; настройки клиента позволяют сменить адрес. Режим и игровые функции определяет сервер.

Проверка внешнего сервера 11.11.2026: DNS и ICMP из Android работают; SA:MP info/rules отвечают, версия сервера `omp 1.5.8.0`, разрешённые клиенты `0.3.7, 0.3.DL`. Начальный стандартный handshake не получил ответа ни из игры, ни отдельным запросом с ПК, тогда как локальный сервер вернул cookie. Точная причина без серверного журнала не установлена; вход на внешний сервер не подтверждён.

При длительном ожидании обнаружен нативный сбой в `CPed::Teleport` при очистке/клонировании facial tasks. Экран подключения удерживал позицию через виртуальный `SetPosn` каждый кадр. В этом пути позиция теперь меняется через transform с обнулением скорости, без повторной очистки задач. Отчёт проверки: `port/reports/sile-controls-runtime.json`.

Адрес переключён на `s1.sile.games:7777` по запросу пользователя. На этом сервере начальный handshake и InitGame проходят; зафиксирован серверный DISCONNECTION_NOTIFICATION. В клиенте исправлено последующее обращение к `remoteSystemList[0]` из `RakClient::GetStatistics`, когда `Disconnect` уже освободил список. Серверное закрытие переводит клиент в DISCONNECTED и прекращает обработку подключённой сессии и автоматические повторы. Для диагностики нативных адресов CMake сохраняет host-side `libsamp.map`; карта не включается в APK.

Проверка исправления на `s1.sile.games:7777`: соединение принято, сервер передал InitGame и закрыл сеанс примерно через 10 секунд без поясняющего сообщения. Клиент остался запущен более 102 секунд после разрыва, повторного соединения и SIGSEGV не было. Пароль/регистрация не отправлялись. Итоговая сборка: `artifacts/samp-mobile-2.10-arm64-sile-s1-debug.apk`; отчёт: `port/reports/s1-server-connection.json`.

## HWID Sile (выключен до явного разрешения)

Причина разрыва через 9–10 секунд подтверждена пользователем по серверному журналу: мод не получил HWID. В предоставленном `gamemodes/include/new-v2-runtime.inc`, `PCode_ClientPacket_HandlePacket215` (исходный диапазон 0x37E364), фактический обработчик читает заголовок `uint8 215 / uint16 1 / uint32 0`, байт платформы, затем две строки с 32-битной длиной. В поле PlayerData со смещением 14148 записывается ВТОРАЯ строка. В старом читаемом `8.7/gamemodes/ess.pwn` порядок иной, поэтому ориентируемся на текущий обработчик.

Добавлен отдельный пакет и JNI-получение идентификатора. Передача разрешается только для `s1.sile.games` / `37.230.210.231`, после InitGame. Модель устройства — фактические Build.MANUFACTURER / Build.MODEL, HWID — SHA-256 от Android ID с областью приложения. Если Android ID недоступен, используется сохранённый UUID установки. Сам Android ID не передаётся. HWID не доступен WebView и не записывается в клиентский журнал. Учётные данные не отправляются.

Без явно установленного `sile_device_identity = 1` в секции `[client]` настройки по умолчанию запрещают даже чтение Android ID. Подготовленный APK содержит `sile_device_identity = 0`. Автопроверка отклонила первоначальную активацию: для передачи модели и стабильного идентификатора на внешний сервер запрошено отдельное согласие пользователя. До его получения конфигурация эмулятора не меняется и сетевой тест HWID не выполняется. Серверные проверки и мод на рабочем столе не изменялись.

Проверка wire-формата: настоящий C++ encoder собран NDK для x86_64 и исполнен в Android на фиктивных строках, без сети и без Android API идентификатора. Независимый Python decoder проверил точные ширины полей, порядок двух строк и отсутствие лишних байт. Проверены границы длины, NUL, недопустимый HWID и список разрешённых хостов. Отчёты: `port/reports/sile-identity-wire-test.json`, `port/reports/sile-hwid-integration.json`.

После явного ответа пользователя «Да, включить передачу HWID» передача модели и хеша разрешена только на `s1.sile.games:7777`. На установленном клиенте включён флаг `[client] sile_device_identity = 1`; исходные настройки и APK по умолчанию остаются с флагом 0 для новых установок. APK установлен, пакет 215/style 1 отправлен после InitGame, HWID длиной 64 символа; само значение в журнал не выводится. Начальная проверка: соединение держится более 37 секунд вместо прежнего отключения через 9–10 секунд. Учётные данные не передавались. Итоговая проверка отражена в `port/reports/sile-hwid-integration.json`.
