# GTA Mobile: локальный HTML-интерфейс

По последующему запросу пользователя основным интерфейсом стал полный веб-кэш Sile Online. Его подключение описано в [SILE-CACHE.md](SILE-CACHE.md). Собственный интерфейс Vue, описанный ниже, сохранён как резервный при ошибке загрузки Sile.

## Поток событий

`Vue → window.client.postMessage(JSON) → Java WebUiController → JNI webUiPost → ограниченная очередь → WebUi::Process в MainLoop → CNetGame`

`C++ → CJavaWrapper::EmitWebUiMessage → Java onWebUiMessage(byte[]) → UI Handler → WebView.evaluateJavascript → window.gtaUi.receive → подписчики Vue`

Обращения к игровым объектам и отправка команд происходят в игровом потоке. WebView не вызывает игровые методы из своего JavaScript-потока. Все обращения к Android View выполняет главный Android-поток.

## Исходники

- `webui/src/bridge.js`: версия протокола, идентификаторы запросов, ответы, таймауты, подписки, отмена ожиданий при сворачивании.
- `webui/src/App.vue`: стек окон `menu`, `chat`, `settings`; живая телеметрия; команды; две клавиатуры; история отправленных строк в пределах сеанса.
- `webui/src/style.css`: собственное оформление и адаптация под высоту окна и IME.
- `app/src/main/java/com/samp/mobile/game/ui/web/WebUiController.java`: WebView, локальные ресурсы, маршрутизация событий, захват касаний, Android IME, жизненный цикл.
- `app/src/main/java/com/samp/mobile/game/SAMP.java`: владелец контроллера, JNI callbacks, обработка аппаратных клавиш при открытом окне.
- `app/src/main/cpp/samp/webui/WebUi.cpp`: очередь, исполнение событий, публикация игрового состояния, снятие удерживаемых касаний.
- `app/src/main/cpp/samp/java/jniutil.cpp`: обратный мост в Java, передача UTF-8 через byte[].

## Протокол v1

Запрос JavaScript:

```json
{"v":1,"id":42,"event":"Client.Command","args":[{"text":"/veh 411"}]}
```

Ответ:

```json
{"replyTo":42,"ok":true,"result":{"sent":true}}
```

Ошибка:

```json
{"replyTo":42,"ok":false,"error":"Нет подключения к серверу"}
```

Событие игры:

```json
{"event":"State","args":[{"connected":true,"health":100,"armour":0,"speed":0,"position":{"x":1759,"y":-1898,"z":113}}]}
```

`id: 0` означает событие без ожидания ответа. `args` всегда массив. `engine.on(name, callback)` подписывает на события игры и возвращает функцию отписки; `engine.trigger(name, ...args)` отправляет событие в Java. Полноценный запрос с ответом доступен через объект моста внутри приложения Vue.

Поддерживаемые события JavaScript:

| Событие | Обработка | Аргумент |
| --- | --- | --- |
| `Ui.Ready` | Java и игровой поток | `{protocol:1}` |
| `Ui.Ping` | игровой поток | `{}` |
| `Ui.RequestState` | игровой поток | `{}` |
| `Ui.Focus` | Java, атомарный флаг в C++ | `{active:true}` |
| `Ui.HitRegions` | Java | `{regions:[{left,top,right,bottom}]}` в долях размеров WebView |
| `Ui.Keyboard` | Java | `{native:true}` |
| `Client.Command` | игровой поток | `{text:"/spawn"}` |
| `Client.Chat` | игровой поток | `{text:"сообщение"}` |

Игра отправляет `State` четыре раза в секунду, а также `Ui.Open` для открытия окна. Java отправляет `Ui.Back` и `Ui.Reset`. Из игрового кода окно открывается вызовом `WebUi::Open("menu")`. Серверные RPC для новых интерфейсов пока не добавлены; команды меню используют существующие `/spawn`, `/respawn`, `/tp`, `/veh` локального сервера. Успешный ответ означает передачу команды в сетевой клиент; подтверждение действия приходит обычным серверным чатом/состоянием игры.

## Ввод и жизненный цикл

Когда окон нет, Android передаёт в WebView только касания кнопки «МЕНЮ». Остальные жесты целиком получает лежащая ниже GTA. При открытом окне WebView получает весь жест, а нативный обработчик дополнительно блокирует игровые касания. При захвате фокуса игровой поток отпускает ранее нажатые указатели. Пед не замораживается, физика не блокируется.

Стек окон сохраняет владение фокусом до закрытия последнего окна. NvEventQueueActivity обходил Activity.onBackPressed для аппаратной кнопки Back; SAMP.onKeyDown/onKeyUp перехватывают этот путь при активном WebUI. Унаследованный путь управления используется после закрытия окон. Клавиши громкости сохраняют системное поведение.

Android IME изменяет доступную высоту только слоя WebView через WindowInsets (API 30+). Игровая SurfaceView не пересоздаётся. На старых Android адаптация к IME требует отдельной проверки. На BlueStacks включён `show_ime_with_hard_keyboard=1`, чтобы системная клавиатура показывалась рядом с клавиатурой ПК. Настройка выбора клавиатуры хранится локально, текст сообщений не сохраняется на диск.

При паузе фокус отпускается, WebView приостанавливается. Кнопка нового меню скрывается, когда игровой цикл перестаёт присылать состояние: после возврата из фона сразу, при штатном меню паузы — по таймауту 1,5 с. Это освобождает кнопку «Возобновить» GTA. При возобновлении игрового цикла кнопка WebUI возвращается. При возврате закрываются открытые окна и обновляется состояние. Состояние игры во время паузы объединяется в последний снимок; прочие ожидающие сообщения ограничены 32. Остановка renderer снимает захват ввода и скрывает слой интерфейса.

## Загрузка и ограничения

Ресурсы собраны в APK и загружаются через WebViewAssetLoader с `https://appassets.androidplatform.net/assets/webui/index.html`. Внешние запросы и переходы блокируются. Доступ WebView к файловым/content URI выключен. Java принимает только разрешённые имена событий. Максимум пакета — 16 КиБ, игровой очереди — 64 пакета. Чат ограничен 144 байтами после преобразования в кодировку SA:MP, NUL и переносы строк запрещены. Данные текста не пишутся в журнал. Отладка WebView включается только для debug APK.

## Сборка

Нужны Node.js 20.19+ и npm, а также обычное окружение сборки Android проекта. Зависимости фиксирует `package-lock.json`.

```powershell
.\Build-WebUi.ps1 -InstallDependencies
npm --prefix webui test
.\Build-Apk.ps1 -Workers 2
```

`Build-Apk.ps1` автоматически пересобирает веб-ресурсы перед Gradle. Выход Vite: `app/src/main/assets/webui`. Для просмотра в настольном браузере: `npm --prefix webui run dev`; вне Android используется явно обозначенный предпросмотр, команды на сервер не отправляются.

Проверки протокола находятся в `webui/tests/bridge.test.js`. Итоговая проверка устройства и APK описана в `port/reports/webui-runtime.json`.
